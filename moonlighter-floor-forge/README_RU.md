# Moonlighter Floor Forge 0.5.3 — приключения в стиле Moonlighter для Foundry VTT v13

Независимый фанатский модуль, **не связан с разработчиками Moonlighter**. Работает с Foundry VTT v13; предназначен прежде всего для системы D&D 5e. Карты, персонажи и предметы **не входят** в поставку.

> **Статус:** проект протестирован синтаксически, геометрически и на эмуляции документного API Foundry, но не проходил испытания внутри запущенного Foundry v13. Создайте резервную копию мира и начните с отдельного тестового мира. Указанная совместимость v13 — целевая версия API, а не подтверждение производственного качества.

## Обновление v0.5.3 — переходы и точные стены

**Стены не по рисунку.** Откройте библиотеку комнат, выберите комнату и разметьте её контур инструментом «Стена» (два клика, можно снять привязку к сетке). Снимите флажок «Создавать внешние стены автоматически по краю картинки», если стены уже обведены вручную. Сохраните разметку. Новые этажи не будут накладывать дополнительный прямоугольник по краям PNG. Дверные сегменты всё равно создаются на отмеченных проёмах.

**Перенос через открытые двери.** В генераторе включён «Автопереход через дверь». При приближении персонажа игрока к открытой связанной двери, модуль переносит его внутрь соседней комнаты этой же сцены. Закрытые и запертые двери не работают. Переход требует свободного места на выходе; модуль не переносит персонажа в яму или на занятый токен. Опция доступна только для вновь сгенерированных этажей. Проверяйте без паузы Foundry.

**NPC.** Токены теперь позиционируются с учётом локальной сетки комнаты, даже если комнаты смещены на дробную часть клетки. Для гарантированного размещения рисуйте зоны «NPC» на свободной части пола; используйте монстров, импортированных в Actors, и следите за предупреждением о пропущенных объектах.

**Ямы.** Надписи и техническая разметка скрыты от игроков на новых сценах. Однако яма, уже нарисованная на PNG-карте, видна всем. При входе персонажа в зону ямы появится предупреждение ведущему, но автоматическое падение/урон не применяется.

**Важно:** любые изменения схемы порталов, стен или появления NPC действуют только при повторной генерации этажа. Перед обновлением мира сохраните резервную копию. Автоматические проверки проходят, но тестирование в запущенной Foundry v13 ещё необходимо.

## Разметка и генерация в v0.5.2

1. Подготовьте изображения отдельных комнат (предпочтительно 8–12 разных вариантов).
2. В **Библиотеке комнат** создайте шаблон, выбрав PNG/WebP. Если сетка изображения не совпадает, вручную задайте точное число клеток по горизонтали и вертикали.
3. На границе комнаты выберите «Дверь» или «Проход»; включённое по умолчанию «Двери без привязки к сетке» позволяет щёлкнуть в любой точке стороны. У обеих стыкуемых дверей должна совпадать ширина. «Стена» — два клика; привязку стен можно отключить.
4. Нажмите «Сохранить разметку». Реальные стены появятся в шаблонной сцене, а данные будут использованы при сборке новых этажей.
5. Откройте **Генератор**, выберите режим «Собрать из комнат» и укажите число помещений. В разделе «Враги» требуется импортированный NPC из Actors (Moonlighter Bestiary импортируйте отдельно). Для лута понадобятся предметы из Items. При использовании Item Piles сундуки будут интерактивными.
6. После создания откройте новую сцену: персонажи переходят между комнатами по обычным дверям и проходам на той же сцене; переход между этажами — через панель ведущего.
7. При входе персонажа в разметку «Яма» ведущему выводится предупреждение, но автоматических бросков, падения и урона пока нет. Технические подписи не показываются игрокам.
8. Чтобы проверить передвижение персонажей, снимите паузу Foundry. Старые сгенерированные сцены не перестраиваются автоматически, создайте новый этаж.

**Важно:** из одной и той же PNG-комнаты генерируется повторяющаяся графика; для разнообразия понадобятся другие изображения. Межклеточное расположение двери гарантирует геометрическое совпадение проёмов, но не изменяет нарисованную на исходном PNG архитектуру.

## Новое в 0.5.0 — рынок артефактов и магазин Item Piles

**Новая кнопка в инструментах токенов: «Moonlighter — рынок, оценка добычи и торговцы»** (доступна ведущему). Настройки спроса хранятся в скрытой **мировой настройке**, общей для всех игровых сцен; один рынок на мир.

### Что умеет рынок

1. **День рынка:** счётчик дней и пять категорий спроса — артефакты, снаряжение, расходники, материалы и прочее. По кнопке **«Следующий день»** коэффициент каждой категории случайно изменяется в пределах ±10% от текущего (общий диапазон 0,60–1,50).
2. **Оценка добычи:** кнопка «Оценить предметы» показывает стоимость предметов выделенного на сцене персонажа; если персонаж не выделен или его инвентарь пуст, используются предметы мира из выбранной папки. Расчёт: `цена D&D5e в gp × спрос`, а если у предмета нет цены — ориентировочная базовая стоимость, зависящая от редкости. Оценка **не изменяет** оригинальные предметы.
3. **Создание торговца Item Piles:** выберите папку предметов, название лавки, количество товаров, наценку (50–200%) и координаты на активной сцене. Кнопка **«Создать торговца»** создаёт интерактивного NPC-торговца Item Piles с **отдельными копиями** предметов и актуальными ценами. Покупка и продажа работают через **интерфейс Item Piles**, а не через собственный незащищённый перевод валюты.

**Важно:** цена товаров назначается при **создании торговца**. Уже существующие торговцы не переоцениваются при смене дня, а стоимость предметов, которые персонажи продают Item Piles торговцу, рассчитывается механизмами самого Item Piles и его настройками. Это **не** симуляция покупателей, дневного оборота магазина или автоматической книги продаж — такие функции пока не реализованы. Пополнение и комиссии задаются в нативном интерфейсе торговца. Item Piles и его D&D5e-адаптер должны быть включены.

### Как быстро проверить v0.5

1. Установите ZIP, перезапустите Foundry v13, включите **Item Piles** и **Item Piles: D&D 5e**.
2. В тестовом мире откройте сцену, создайте пару предметов с ценой `system.price` или добавьте готовые предметы мира.
3. Откройте панель **Рынок**, нажмите **Оценить предметы**, затем **Следующий день** и сравните цены.
4. Выберите папку товаров, укажите координаты и нажмите **Создать торговца**. Откройте новый токен через Item Piles, проверьте отображение товаров и расчёт валюты на тестовых персонажах.
5. Если Item Piles выключен, оценка и изменения рынка остаются доступны, но создание торговца правильно выдаёт предупреждение.

## Новое в 0.4.0 — интеграция с Item Piles

**Интеграция опциональная.** Для интерактивной добычи установите и включите:

- [Item Piles](https://foundryvtt.com/packages/item-piles/) — основной модуль (с его зависимостями, устанавливаемыми Foundry).
- [Item Piles: D&D 5e](https://foundryvtt.com/packages/itempilesdnd5e) — отдельная системная интеграция для D&D 5e.

В генераторе в разделе **4. Добыча** появилась настройка **Режим контейнеров**:

- **Автоматически** — использовать Item Piles при наличии обоих активных модулей; иначе использовать тайники из 0.3.0.
- **Только Item Piles** — не начинать генерацию, если интеграция недоступна.
- **Старые тайники** — всегда создавать журнал и отметки, выдача через ведущего.

Если Item Piles доступен, каждый тайник создаётся **реальным токеном-контейнером** с отдельным содержимым на созданной сцене. Игроки взаимодействуют с токенами стандартным интерфейсом Item Piles, включая передачу предметов. Содержимое таких сундуков хранится непосредственно Item Piles, а не дублируется списком наград в состоянии Moonlighter. После опустошения сундук остаётся на карте (`deleteWhenEmpty: false`).

На вкладке **Управление этажом** сундуки Item Piles отображают актуальный статус: *есть добыча*, *пуст*, *отключён* или *токен не найден*. Ведущий может открыть интерфейс контейнера кнопкой. Кнопки **«Выдать»** для них нет, чтобы не создавать дубликаты предметов.

**Обновление существующего подземелья 0.3.0:** откройте ранее созданный процедурный этаж → **Управление этажом** → **Перевести старые сундуки в Item Piles**. Конвертация переносит только **неполученные** сундуки, требует старую отметку Journal Note и после успешной записи новых данных удаляет прежние иконки (Note/Tile). Уже выданные сундуки пропускаются. Сохраните резервную копию мира перед конвертацией. Исторический журнал ведущего не удаляется.

Изображение сундука пока берётся из стандартного значка Foundry `icons/svg/chest.svg`; оформление и звуки можно будет расширить в следующей версии. Система рыночной оценки и создание торговцев реализованы в v0.5.0; проклятые артефакты и полноценное моделирование покупателей пока не включены.

## Что появилось в 0.3.0

- **Типы комнат** в редакторе шаблонов: случайная, вход, боевая, сокровища, отдых, тайная, босс.
- **Боевые арены**: когда группа вошла в комнату, двери Foundry блокируются. После победы (0 HP у NPC с известным HP либо удалённые вражеские токены) открываются. Можно запустить/закончить бой вручную.
- **Групповой триггер по умолчанию**: блокировка начинается только когда **все живые персонажи игроков, чьи токены присутствуют на этой сцене**, находятся внутри комнаты. Можно переключить на первого персонажа или полностью ручной режим.
- **Тайные комнаты** только в тупиках: скрытый проход не разрывает обязательный маршрут. Скрытые двери в Foundry (door=2); ведущий раскрывает их через панель управления.
- **Сундуки на карте** (тайлы + значки журнала): полученные предметы теперь можно выдать в реальный инвентарь персонажа D&D5e. Копируется содержимое мировых Item. Повторная выдача уже полученного тайника блокируется.
- **Несколько этажей** (1–4): отдельные сцены, связи «предыдущий/следующий этаж» в панели ведущего. На следующих этажах увеличивается число NPC и, при заданном ограничении CR, максимальный CR. Назначенный босс появляется на финальном этаже.
- **Панель управления этажом**: вручную начать и завершить бой, открыть тайный проход, посмотреть тайники, выдать предметы персонажу, открыть следующую сцену.
- Все функции версии **0.2.0** сохранены: загрузка изображений комнат; редактор дверей/стен/укрытий/ям/зон; соединение дверей при поворотах; генерация NPC, лута и босса.

## Установка или обновление

1. Выключите Foundry и сделайте **резервную копию мира**.
2. Распакуйте архив так, чтобы был путь:
   `FoundryVTT/Data/modules/moonlighter-floor-forge/module.json`.
   В обычной установке Windows User Data Path часто находится по адресу `%LOCALAPPDATA%/FoundryVTT/Data/`.
3. Замените файлы предыдущей версии. Не создавайте вложенную папку `moonlighter-floor-forge/moonlighter-floor-forge/`.
4. Перезапустите Foundry, включите **Moonlighter Floor Forge** в тестовом мире через «Управление модулями».
5. На панели инструментов **Tokens** у ведущего появятся четыре кнопки: **Библиотека комнат**, **Управление этажом**, **Рынок и торговцы**, **Создать подземелье**.

В консоли F12 доступны ручные команды:

```js
game.moonlighterFloorForge.rooms()     // Библиотека комнат
game.moonlighterFloorForge.open()      // Генератор
game.moonlighterFloorForge.director() // Панель управления текущей сценой
```

## Быстрый запуск

1. Нажмите **Библиотека комнат** → **Загрузить новую комнату**. Загрузите свою PNG/WebP/JPG с одной комнатой. Можно взять фон существующей сцены, но не её предметы/тайлы и стены.
2. В редакторе мышью отметьте двери/проходы по краям, внутренние стены, укрытия, ямы и при желании области `SPAWN`, `LOOT`, `BOSS`.
3. Выберите **Тип комнаты** над редактором: например, «Сокровища», «Боевая», «Отдых», «Тайная»; при желании создайте шаблоны входа и босса. Нажмите **Сохранить разметку**.
4. Подготовьте несколько комнат с 2–4 дверями и хотя бы одну комнату-тупик (1 дверь). Выберите **Создать подземелье**.
5. Выставьте количество комнат, этажей, вероятность тайников, NPC, CR, качество лута и режим блокировки дверей. В разделе «Добыча» выберите **Автоматически** или **Только Item Piles**. Выберите папку NPC, папку предметов и босса.
6. Генератор создаст новые сцены. Через **Управление этажом** можно управлять боем, секретами и содержимым сундуков.
7. Если включён Item Piles, игрок открывает токен сундука на сцене и забирает предметы в своём интерфейсе; ведущий может посмотреть его через «Управление этажом». При старом режиме ведущий по-прежнему выбирает сундук, персонажа и нажимает «Выдать».

### Быстрый вызов торговой панели

`game.moonlighterFloorForge.market()` — открывает рынок. `game.moonlighterFloorForge.marketState()` — показывает рыночные коэффициенты.

## Важные правила работы

- **Визуальная разметка остаётся ручной.** Модуль не распознаёт фактические стены или двери по пикселям PNG.
- Двери на внешних сторонах комнаты имеют ширину **ровно одну клетку**. Если соединены два прохода без дверей, проход остаётся открытым и автоматически блокироваться не может. Для боевых помещений помечайте входы как **Дверь**.
- Ведущий должен выбрать **NPC из мирового списка Actors**. Новые NPC копируются в виде токенов, а не как новые World Actors.
- Автоматическое определение победы работает, когда NPC удалены, получили статус `dead` или их системный HP снизился до 0. Для нестандартных эффектов «повержен» используйте кнопку **Зачистить** вручную. HP и статус смерти интерпретируются как упрощённая логика, а не полные правила D&D.
- В режиме «вся группа» проверяются живые видимые токены Actors с `hasPlayerOwner` на данной сцене. Если кто-то из группы находится в другом помещении, двери ещё не заблокируются. Если персонажей нет, ведущий может начать бой вручную.
- Секретные помещения ставятся только в тупиках. «Тайная» на шаблоне, оказавшаяся проходной комнатой, будет обычной боевой комнатой; это защищает связность основного маршрута.
- Шаблон типа **Вход** при наличии предпочитается для первой комнаты; шаблон **Босс** по возможности выбирается для последней комнаты. Это предпочтение, а не гарантия при недостатке совместимых дверных проёмов.
- Начальный и конечный этажи связаны только **кнопками выбора сцен для ведущего**. **Автоматической телепортации токенов игроков, активации сцены для всех или сохранения положения персонажей между этажами пока нет**.
- **С Item Piles** сундуки являются интерактивными токенами, а их содержимое передаёт Item Piles. **Без Item Piles или в ручном режиме** журнал остаётся приватным, а сундуки выглядят как тайлы/Notes и выдаются ведущим из панели.
- **Отдых** пока тип комнаты без автоматического лечения или восстановления ресурсов. **Укрытия** и **ямы** размечаются и учитываются при размещении NPC, но бонусы укрытия, падение и урон не применяются автоматически.
- Модуль **не** строит навигационную сетку, не проверяет полностью проходимость всех проходов за декорациями, не размечает большую PNG на комнаты автоматически.
- Указанный шанс тайной комнаты применяется только к пригодным тупиковым комнатам. При отсутствии тупиков тайных помещений не будет.
- При неудачной сборке этажа он может содержать меньше комнат, чем указано. При ошибке во время генерации нескольких этажей уже созданные сцены останутся в мире; их нужно проверить и при необходимости удалить вручную.
- В режиме «Одна PNG» или «Копия сцены» работает генерация врагов и тайников. **Item Piles работает во всех режимах**, если модули активны. Боевые арены, секреты, управление сундуками через панель и многосценовые экспедиции включены только для режима сборки из комнат.

## Техническая структура

- `module.json` — манифест, версия и совместимость.
- `scripts/room-core.mjs` — размещение тайлов, повороты, совпадение дверей, стены, зоны.
- `scripts/room-editor.mjs` — редактор ручной разметки и типов комнат.
- `scripts/adventure-core.mjs` — чистая логика типов комнат, размещения группы, победы, переноса данных предметов.
- `scripts/expedition.mjs` — боевые состояния, секреты, сундуки, панель GM и Hooks.
- `scripts/item-piles.mjs` — опциональный адаптер API Item Piles, создание контейнеров и конвертация старых сундуков.
- `scripts/main.js` — генератор, UI, создание сцен, NPC, лута, этажей.
- `scripts/market-core.mjs` — расчёт стоимости, категории товаров и изменение спроса.
- `scripts/market-piles.mjs` — создание торговцев через официальный публичный API Item Piles.
- `scripts/market-ui.mjs` — панель рынка, оценка инвентаря, создание лавки и скрытая настройка спроса.
- `tests/` — тесты геометрии и мок-среды.

На компьютере с Node.js можно запустить:

```bash
node tests/geometry.test.mjs
node tests/adventure.test.mjs
node tests/mock-foundry.test.mjs
node tests/item-piles.test.mjs
node tests/market.test.mjs
```

Официальный API: https://foundryvtt.com/api/v13/ . Состояния дверей: CLOSED=0, OPEN=1, LOCKED=2; типы дверей: DOOR=1, SECRET=2.

## Ограничения и статус тестирования v0.5

- Интеграция использует публичные `game.itempiles.API.createItemPile`, `isItemPileEmpty` и `renderItemPileInterface`, но пока **не проверена в реальном запущенном Foundry v13**. Есть статическая проверка JS и тесты с имитацией Foundry/Item Piles API. Не устанавливайте в основной мир без резервной копии.
- Конвертация сундуков требует старых Notes; **уже забранные предметы не конвертируются**. В случае ошибки посмотрите уведомление и консоль F12; не запускайте повторное создание без проверки дублирующих токенов.
- Неполадка API в процессе генерации прерывает создание этажа, чтобы не дублировать добычу. Частично созданные сцены при ошибке нужно проверить вручную.
- Звук/анимации/слоты рюкзака Moonlighter пока не связаны с Item Piles. Время появления предметов в токене после создания определяется внутренней логикой Item Piles.
